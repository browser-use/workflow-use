## Workflow Structure

A workflow YAML file has the following top-level structure:

```yaml
workflow_analysis: <optional analysis text>
name: <workflow name>
description: <workflow description>
version: <version string>
input_schema: <list of input parameters>
steps: <list of workflow steps>
```

---

## Workflow Metadata

### Required Fields

- **name** (string): The name of the workflow
- **description** (string): A brief description of what the workflow does
- **version** (string): Version number (e.g., "1.0")
- **steps** (list): Array of step objects to execute

### Optional Fields

- **workflow_analysis** (string): Detailed analysis of the workflow, typically generated by AI
- **input_schema** (list): Array of input parameter definitions (empty if no inputs needed)

---

## Input Schema

Define workflow inputs that can be passed when executing the workflow:

```yaml
input_schema:
  - name: repository_name        # Parameter name
    type: string                 # Type: "string", "number", or "boolean"
    required: true               # Whether this parameter is required
    description: The repo name   # Optional description

  - name: max_results
    type: number
    required: false
    description: Maximum number of results to return
```

**Accessing inputs in steps**: Use `{parameter_name}` placeholder syntax:
```yaml
url: https://github.com/search?q={repository_name}
```

## Step Types

### 1. Navigation Step

Navigate to a URL.

```yaml
- type: navigation
  description: Navigate to GitHub
  url: https://github.com
  output: null  # Optional: variable name to store result
```

**Fields**:
- `url` (required): The URL to navigate to (supports placeholders)
- `description` (required): Description of the step
- `output` (optional): Variable name to store output

---

### 2. Click Step

Click on an element using semantic targeting.

```yaml
- type: click
  description: Click the Sign In button
  target_text: Sign in
  output: null
```

**Fields**:
- `target_text` (required): Semantic description of element to click
- `description` (required): Step description
- `output` (optional): Variable name to store result
- `cssSelector` (deprecated): Legacy CSS selector
- `xpath` (deprecated): Legacy XPath selector

**Note**: Use `target_text` for semantic targeting instead of CSS/XPath selectors.

---

### 3. Input Text Step

Enter text into an input field.

```yaml
- type: input
  description: Enter username
  target_text: Username
  value: john.doe@example.com
  default_value: default_user@example.com  # Optional: Used if value is empty or placeholder not found
  output: null
```

**Fields**:
- `target_text` (required): Semantic description of input field
- `value` (required): Text to enter (supports placeholders like `{variable_name}`)
- `default_value` (optional): Default value to use if `value` is empty or context variable is not available
- `description` (required): Step description
- `output` (optional): Variable name to store result

**Example with default value**:
```yaml
- type: input
  description: Enter optional search term
  target_text: Search
  value: '{search_query}'  # From context/input parameter
  default_value: '*'        # Use '*' if search_query is not provided
  output: null
```

---

### 4. Select Option Step

Select an option from a dropdown.

```yaml
- type: select_option
  description: Select country
  target_text: Country
  value: United States
  output: null
```

**Fields**:
- `target_text` (required): Semantic description of dropdown
- `value` (required): Option text to select
- `description` (required): Step description
- `output` (optional): Variable name to store result

---

### 5. Checkbox Step

Check or uncheck a checkbox.

```yaml
- type: checkbox
  description: Accept terms and conditions
  target_text: I agree to the terms
  checked: true  # true to check, false to uncheck
  output: null
```

**Fields**:
- `target_text` (required): Semantic description of checkbox
- `checked` (required): Boolean - true to check, false to uncheck
- `description` (required): Step description
- `output` (optional): Variable name to store result

---

### 6. Extract Page Content Step

Extract information from the current page using AI.

```yaml
- type: extract_page_content
  description: Extract product details
  goal: Extract the product name, price, and availability status
  output: product_info
```

**Fields**:
- `goal` (required): What information to extract
- `description` (required): Step description
- `output` (required): Variable name to store extracted data

---

### 7. Done Step

Mark the workflow as complete.

```yaml
- type: done
  description: Workflow completed successfully
  output: final_result
```

**Fields**:
- `description` (required): Step description
- `output` (optional): Variable name to store result

---

### 8. Agent Step

Use an AI agent to perform complex tasks.

```yaml
- type: agent
  description: Research and summarize
  task: |
    Analyze the current page and create a summary of:
    1. Main topic
    2. Key points
    3. Related links
  max_steps: 10
  output: ai_analysis
```

**Fields**:
- `task` (required): Detailed instructions for the AI agent
- `description` (required): Step description
- `max_steps` (optional): Maximum number of actions the agent can take (default: 10)
- `output` (optional): Variable name to store agent result

## Complete Examples

### Example 1: Simple GitHub Star Counter

```yaml
workflow_analysis: |
  This workflow searches for a GitHub repository and extracts its star count.

name: Get GitHub Repository Stars
description: Find and return the star count for a GitHub repository
version: '1.0'

input_schema:
  - name: repo_name
    type: string
    required: true
    description: Name of the GitHub repository

steps:
  - type: navigation
    description: Navigate to GitHub search
    url: https://github.com/search?q={repo_name}&type=repositories
    output: null

  - type: extract_page_content
    description: Extract star count from first result
    goal: Extract the number of stars for the top repository result
    output: star_count

  - type: done
    description: Complete workflow
    output: final_result
```

---

### Example 2: Form Filling Workflow

```yaml
name: Contact Form Submission
description: Fill out and submit a contact form
version: '1.0'

input_schema:
  - name: user_name
    type: string
    required: true
  - name: user_email
    type: string
    required: true
  - name: message
    type: string
    required: true

steps:
  - type: navigation
    description: Go to contact page
    url: https://example.com/contact
    output: null

  - type: input
    description: Enter name
    target_text: Your Name
    value: '{user_name}'
    output: null

  - type: input
    description: Enter email
    target_text: Email Address
    value: '{user_email}'
    output: null

  - type: input
    description: Enter message
    target_text: Message
    value: '{message}'
    output: null

  - type: select_option
    description: Select topic
    target_text: Topic
    value: General Inquiry
    output: null

  - type: checkbox
    description: Accept privacy policy
    target_text: I accept the privacy policy
    checked: true
    output: null

  - type: click
    description: Submit form
    target_text: Submit
    output: null

  - type: done
    description: Form submitted
    output: submission_result
```

---

### Example 3: Research with AI Agent

```yaml
name: Product Research Workflow
description: Research a product and create a detailed analysis
version: '1.0'

input_schema:
  - name: product_url
    type: string
    required: true

steps:
  - type: navigation
    description: Navigate to product page
    url: '{product_url}'
    output: null

  - type: agent
    description: Analyze product details
    task: |
      Please analyze this product page thoroughly:
      1. Extract the product name and price
      2. Read and summarize customer reviews
      3. List key features and specifications
      4. Note any current promotions or discounts
      5. Assess overall value for money

      Provide a comprehensive analysis.
    max_steps: 15
    output: product_analysis

  - type: done
    description: Research complete
    output: final_report
```

## Variable Substitution

You can use outputs from previous steps in later steps using `{variable_name}` syntax:

```yaml
steps:
  - type: extract_page_content
    description: Get username
    goal: Extract the username from profile
    output: username  # Store in 'username' variable

  - type: input
    description: Enter the username
    target_text: Search
    value: '{username}'  # Use the extracted username
    output: null
```

---

## Notes

1. **YAML Comments**: Use `#` for comments
2. **Multi-line Strings**: Use `|` for multi-line text (preserves newlines) or `>` for folded text
3. **Null Values**: Use `null` for empty/null values
4. **Boolean Values**: Use `true` or `false` (lowercase)
5. **Quotes**: Generally optional but recommended for strings with special characters
6. **File Extension**: Workflows should be saved with `.yaml` or `.yml` extension

## Migration from JSON

If you have existing JSON workflows, they can be converted to YAML programmatically:

```python
import json
import yaml

# Read JSON
with open('workflow.json', 'r') as f:
    data = json.load(f)

# Write YAML
with open('workflow.yaml', 'w') as f:
    yaml.dump(data, f, default_flow_style=False, sort_keys=False)
```

The data structure remains the same; only the serialization format changes.
